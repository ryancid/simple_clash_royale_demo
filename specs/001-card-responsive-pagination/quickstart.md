# Quick Start Guide: 卡片頁面響應式分頁優化

**Date**: 2025-12-06
**Feature**: 001-card-responsive-pagination

## 目的

本指南提供開發者和測試者快速驗證響應式卡片網格和智慧分頁功能的步驟。

---

## 環境準備

### 前置條件

1. **Node.js** >= 18.7
2. **.env.local** 檔案包含有效的 `API_KEY`
   ```bash
   # .env.local
   API_KEY=your_clash_royale_api_key
   ```
3. **依賴套件**已安裝
   ```bash
   npm install
   ```

### 快速啟動

```bash
# 開發模式
npm run dev

# 開啟瀏覽器
open http://localhost:3000/cardList
```

## 功能驗證場景

### 場景 1：響應式網格佈局（P1 MVP）

**目標**：驗證卡片網格在不同螢幕尺寸下都能整齊對齊

#### 步驟 1-1：桌面檢視
1. 在瀏覽器開啟 `http://localhost:3000/cardList`
2. 確保視窗寬度 ≥ 1024px（桌面尺寸）
3. **預期結果**：
   - ✅ 每一排顯示 4 張以上的卡片
   - ✅ 每一排的卡片數量一致（例如都是 6 張）
   - ✅ 卡片整齊對齊，沒有參差不齊

#### 步驟 1-2：手機檢視
1. 開啟開發者工具（F12）
2. 切換到「Device Mode」（或按 Ctrl+Shift+M）
3. 選擇「iPhone 12」或「Pixel 5」
4. **預期結果**：
   - ✅ 每一排顯示 2-4 張卡片
   - ✅ 每一排的卡片數量一致（例如都是 3 張）
   - ✅ 卡片整齊對齊

#### 步驟 1-3：調整視窗寬度
1. 從桌面尺寸（1920px）開始
2. 慢慢縮小視窗寬度到手機尺寸（375px）
3. **預期結果**：
   - ✅ 卡片網格即時重新排列（< 500ms）
   - ✅ 每個寬度下，所有排的卡片數量都一致
   - ✅ 沒有出現視覺閃爍或佈局錯亂

#### 步驟 1-4：極窄視窗
1. 將視窗寬度縮小到 < 300px
2. **預期結果**：
   - ✅ 每排至少顯示 1 張卡片
   - ✅ 卡片不會消失或重疊

**通過標準**：所有 ✅ 項目都符合預期

### 場景 2：智慧分頁計算（P2）

**目標**：驗證每頁顯示的卡片數量是「每排數量」的倍數

#### 步驟 2-1：桌面分頁
1. 在桌面尺寸（1920px）開啟 `http://localhost:3000/cardList`
2. 觀察第一頁的卡片排列
3. 計算：每排卡片數量（例如 8 張）× 每頁排數（4 排）= 32 張
4. 點擊「下一頁」按鈕
5. **預期結果**：
   - ✅ 第一頁顯示 32 張卡片（8 × 4）
   - ✅ 第一頁的最後一排是完整的 8 張
   - ✅ 第二頁的第一排也是完整的 8 張
   - ✅ 沒有某一排被分頁切斷

#### 步驟 2-2：手機分頁
1. 切換到手機尺寸（375px）
2. 觀察第一頁的卡片排列
3. 計算：每排卡片數量（例如 3 張）× 每頁排數（4 排）= 12 張
4. 點擊「下一頁」按鈕
5. **預期結果**：
   - ✅ 第一頁顯示 12 張卡片（3 × 4）
   - ✅ 分頁邊界不會切斷某一排

#### 步驟 2-3：調整視窗後分頁重新計算
1. 在第 2 頁（不是第 1 頁）
2. 調整視窗寬度，導致每排卡片數量改變
3. **預期結果**：
   - ✅ 自動跳回第 1 頁（避免顯示空頁）
   - ✅ 新的分頁邊界仍然對齊每排

**通過標準**：所有 ✅ 項目都符合預期

---

### 場景 3：分頁導航體驗（P3）

**目標**：驗證分頁導航的正確性和易用性

#### 步驟 3-1：頁碼顯示
1. 開啟卡片列表頁面
2. 檢視分頁控制區域
3. **預期結果**：
   - ✅ 能看到「第 X 頁 / 共 Y 頁」的資訊
   - ✅ 頁碼正確（例如「第 1 頁 / 共 5 頁」）

#### 步驟 3-2：上一頁/下一頁按鈕狀態
1. 在第 1 頁
2. **預期結果**：
   - ✅「上一頁」按鈕是停用的（disabled）
   - ✅「下一頁」按鈕是啟用的

3. 點擊「下一頁」到第 2 頁
4. **預期結果**：
   - ✅ 兩個按鈕都是啟用的

5. 點擊「下一頁」直到最後一頁
6. **預期結果**：
   - ✅「下一頁」按鈕是停用的
   - ✅「上一頁」按鈕是啟用的

#### 步驟 3-3：頁碼跳轉（如果實作）
1. 在分頁控制區域點擊頁碼（例如「3」）
2. **預期結果**：
   - ✅ 直接跳到第 3 頁
   - ✅ 頁面顯示正確的卡片

**通過標準**：所有 ✅ 項目都符合預期

## Edge Cases 驗證

### Edge Case 1：API 回傳空資料
```bash
# 模擬方式：暫時移除 .env.local 的 API_KEY
mv .env.local .env.local.bak
npm run dev
```
**預期結果**：
- ✅ 顯示「目前沒有卡片」或錯誤訊息
- ✅ 不會顯示空白頁面或崩潰

### Edge Case 2：卡片總數很少
如果 API 只回傳 < 10 張卡片：
**預期結果**：
- ✅ 只顯示一頁
- ✅ 分頁資訊顯示「第 1 頁 / 共 1 頁」
- ✅ 上一頁/下一頁按鈕均停用

### Edge Case 3：快速連續調整視窗
1. 快速拖曳視窗邊緣，連續調整 10 次
2. **預期結果**：
   - ✅ 不會出現佈局錯亂
   - ✅ 不會出現 JavaScript 錯誤（檢查 Console）
   - ✅ 不會出現明顯的視覺閃爍

## 效能驗證

### 測試 SC-002：視窗調整重排時間 < 500ms
1. 開啟開發者工具的 Performance 面板
2. 開始錄製
3. 調整視窗寬度
4. 停止錄製
5. **檢查**：從 resize 事件到畫面更新完成 < 500ms

### 測試 SC-006：頁面載入時間 < 3 秒
1. 開啟開發者工具的 Network 面板
2. 勾選「Disable cache」
3. 重新整理頁面（Ctrl+Shift+R）
4. **檢查**：從開始到 DOMContentLoaded < 3 秒

## 已知問題和限制

### 限制 1：不支援 IE 11
- **原因**：使用 ResizeObserver（IE 11 不支援）
- **影響範圍**：IE 11 使用者
- **緩解措施**：顯示「請使用現代瀏覽器」訊息

### 限制 2：不支援虛擬滾動
- **原因**：卡片數量 < 200，不需要
- **影響範圍**：如果未來卡片數量 > 500 可能需要優化
- **緩解措施**：目前無需處理

## 除錯提示

### 問題 1：卡片沒有顯示
**檢查項目**：
1. `.env.local` 是否包含有效的 `API_KEY`
2. Console 是否有錯誤訊息
3. Network 面板檢查 `/api/cards` 是否回傳 200

### 問題 2：每排卡片數量不一致
**檢查項目**：
1. 檢查 `cardsPerRow` 的計算邏輯
2. 檢查 CSS Grid 的 `gridTemplateColumns` 設定
3. 檢查 `gap` 值是否正確

### 問題 3：分頁按鈕狀態錯誤
**檢查項目**：
1. 檢查 `currentPage` 和 `totalPages` 的值
2. 檢查 `canPrevPage()` 和 `canNextPage()` 的邏輯
3. 確認視窗調整時有重置 `currentPage = 0`

## 完整測試檢查清單

### P1: 響應式網格佈局
- [ ] 桌面檢視（≥1024px）每排 ≥ 4 張
- [ ] 手機檢視（≤480px）每排 2-4 張
- [ ] 調整視窗時即時重排（< 500ms）

- [ ] 手機每頁是每排的倍數
- [ ] 分頁邊界不切斷某一排
- [ ] 視窗調整時重置到第 1 頁

- [ ] 顯示「第 X 頁 / 共 Y 頁」
- [ ] 第 1 頁「上一頁」停用

### Edge Cases
- [ ] API 空資料顯示友善訊息
- [ ] 卡片少於一頁顯示「1/1」
- [ ] 快速連續調整視窗不崩潰

### 效能
- [ ] 視窗調整 < 500ms
- [ ] 頁面載入 < 3 秒
